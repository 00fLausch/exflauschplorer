# Feature status

Status as of 2026-09-27. “Done” means implemented and covered by the corresponding automated test. Hardware, iOS, and media benchmarks are separately marked as not verified.

| Area | Status | Notes |
|---|---|---|
| Loopback server, Tailscale identity, login allowlist, CSRF, security headers | Done | Kestrel binds only to `127.0.0.1`; the logged-in Tailscale login is checked against the allowlist and anonymous API calls are rejected. Serve is active on HTTPS port `5180` as a tailnet-only proxy to `127.0.0.1:5180`. The MagicDNS HTTPS page and the PWA loaded with HTTP 200; Funnel is not configured. Real iPhone access remains open under hardware checks. |
| File shares and runtime security settings | Done | **More → Settings → File shares** manages all drives, additional roots, read-only mode, and the default protection for Windows/Program Files. Changes are validated, saved, logged, and take effect immediately in the atomically replaced PathAccessPolicy. Reparse-point resolution uses the same policy snapshot during a request. Unit and WebKit E2E tests check write protection, adding/removing roots, and immediate lockout after removal. |
| Tray app, normal user session, HKCU autostart, setup | Done | No Windows service; no admin required. |
| Drives, Windows user folders, breadcrumbs, open path, back/forward/up | Done | Known folders via the Windows Known Folder API; shows redirections such as OneDrive as reported by Windows. The installed host successfully listed and streamed a 337-character path; `\\?\` normalization, 8.3 short names, Unicode, spaces, and reserved names are additionally tested. |
| Favorites, recently opened, last path | Limited | App favorites are stored in `settings.json` per Tailscale login account, checked against the current share on read, and limited to 100 folders. Already locally saved folder favorites are checked once on upgrade and migrated. Parallel changes to favorites, shares, and PIN serialize on the same settings file. The last folder and up to 80 back/forward positions remain in the local PWA profile and are restored after reload; WebKit E2E checks back and forward after two reloads. History is not synced between devices. Windows Quick Access and “Recently used” are shown when their shell paths are shared. Reading Quick Access uses the Windows shell namespace ID; changes to Windows pins are not available. |
| List/details/grid, sorting, grouping, filtering, paging, virtualized rendering | Limited | Grouping by date, type, or size and filters by type, extension, size, and date are available. The backend keeps up to eight bounded folder views as one-minute snapshots; FileSystemWatcher and explicit refresh invalidate them. An automated test with 50,000 files took 1.83 s for the first page on this PC; the iPhone viewport test kept under 80 file elements in the DOM. Directory queries have a 20-second limit, return a clear error for a hanging drive, and cap a permanently hanging query at one worker per drive or network share. Long press and swipe gesture open the action menu; pull-to-refresh is available on the home page and file list. WebKit checks long press, swipe, and refresh in a folder. Responsive breadcrumb navigation scrolls horizontally for long paths, follows the current position, and offers labeled 44×44 px targets; Playwright checks this on a temporary Windows path. Real slow or remote drives have not been measured. |
| Multi-select, “Select all”, bottom action bar | Done | Selection mode keeps the bar permanently above the bottom navigation. Tapping toggles individual entries; “Select all” asynchronously loads all filtered pages and shows progress. WebKit checks this with 50,000 entries, a 320 px viewport, and touch targets. |
| Hidden files | Done | Toggleable in the folder view and settings. |
| Show/hide system files and file extensions | Done | System attributes have their own switch; file extensions are hidden in the file list, tiles, and “Recent”. Paths and file actions continue to use the real name. |
| Shell thumbnails, cache | Limited | Windows shell thumbnail provider with disk-accessible default behavior; thumbnails are cached by path, size, and modification time. A WebKit iPhone E2E test creates a PNG, checks the shell endpoint's PNG response, and loads the thumbnail in tile view. With `WINDOWS_MOBILE_EXPLORER_HEIC_FIXTURE`, the same test optionally checks a real HEIC file via the Windows shell thumbnail endpoint; on this PC, `example.heic` from the libheif project rendered successfully via the shell thumbnail. The Windows “HEIF Image Extensions” package is installed on this PC; MP4 and PDF thumbnails are checked in the WebKit test via the Windows shell endpoint. Other formats also need a matching shell handler. Formats without a matching handler show the Windows file icon. |
| New folders/text files, rename/sequence pattern, copy/move, internal cut/paste | Done | New files with text, Markdown, JSON, CSV, HTML, and JavaScript templates. Folder picker instead of drag & drop. |
| Recycle bin, permanent delete, restore, replace/skip/keep both, undo | Limited | Default deletion uses the Windows shell with `FOFX_RECYCLEONDELETE`, which explicitly requests the recycle-bin transport instead of permanent deletion. Undo stores up to 50 last job groups; history is consumed only after a successful undo and remains available after a failed attempt. Concurrent undo requests use the same pending job. Live on this PC with a unique test file under `C:\Users\…\AppData\Local\Temp`: moved to the Windows recycle bin via the app, listed there, and restored to the original location. Automated Windows shell tests check delete, list, restore by ID, and undo by original path; integration tests check retry after failed undo and concurrent undo requests. USB and network drives have not been practically validated. |
| ZIP/extract, ZIP download of a folder | Done | ZIP streams the folder download without staging the entire archive beforehand. If 7-Zip is installed under Program Files, `.7z` archives can also be extracted. Entries are written individually to a staging directory after checked path normalization; links and colliding names are rejected. |
| Resolve and follow Windows shortcuts (`.lnk`) | Done | The shell reads the target without executing it. Link chains are followed; each target is normalized and checked against the shares. Integration tests cover Unicode targets, file/folder targets, and blocked targets outside the share. |
| Background jobs, status, progress/speed/ETA, pause/cancel | Limited | Jobs and uploads survive browser close and host restart. Pause/cancel happens at file/chunk boundaries; a blocking shell dialog cannot be interrupted by the app. Cancellation with 10,000 files is covered by an automated test. Move jobs delete only planned files after a cross-platform copy, re-check length and modification time, and remove folders non-recursively; an integration test adds a file after the plan and checks preservation plus undo. A changed source file is left at the origin with a clear error message. |
| iPhone chunked upload, checksums, resume | Limited | 8 MB client chunks, server-side chunk and overall SHA-256, session metadata, and restart/resume. On temporary network loss, the page reconciles the stored server offset and resumes automatically; running uploads can be canceled. E2E simulates a lost chunk response after successful storage. An automated 2 GB test interrupts after 1 GB, reloads the session from metadata, and checks the full SHA-256. If iOS discards the page, the same file must be selected again from Files/Photos; the real iPhone/network-switch test remains open. |
| Download, HTTP Range, video/audio streaming | Limited | The 5 GB range test passed over the real MagicDNS HTTPS serve address: the beginning and end of a 5 GB sparse file returned HTTP 206 and correct Content-Range values. For the provided 293 MB MP3, 32 bytes each at the beginning and end were also read correctly over the same address. A WebKit iPhone viewport E2E test decodes a synthetic two-hour 5 GB H.264 MP4 with repeated valid GOPs. Seeks at 10, 30, 75, and 5,400 seconds pass; the last seek triggers a 206 range request at about byte 3.73 GB. A separate fetch at byte 3.75 GB also returns HTTP 206. The test also checks the normal H.264 clip, MP3 streaming, and scrubbing on the native audio timeline. Real iPhone Safari operation and scrubbing remain to be verified on a physical device. |
| Sharing on iOS | Limited | Files up to 32 MB are passed via the Web Share API with file contents to the native iOS share menu; after a simulated `NotAllowedError`, E2E checks the tappable retry. Large files and folders are downloaded and then shared via the Files app. Safari/iPhone behavior has not yet been tested on a real device. |
| Image, video, audio, PDF, text/code/Markdown preview | Limited | Markdown is formatted and sanitized with DOMPurify; local images are loaded only via the shared stream endpoint. E2E checks rendering, local images, removal of remote raw HTML images including `srcset`, absence of external image requests, and removal of a script tag. The iPhone WebKit test decodes the synthetic video and audio fixture, checks video seeking, taps to seek on the native audio timeline, and verifies that the PDF preview embeds the stream and serves range requests with HTTP 206. Image pinch zoom and photo/media metadata are implemented. Robust PDF rendering across all iOS versions and touch gestures have not yet been accepted on real iPhones. |
| Text editor, save, version conflict | Done | UTF-8/UTF-16 read, atomic replace, SHA-256 ETag, size limit 2 MB; E2E save tested in WebKit. |
| “Open on PC”/“Show in Explorer” | Done | Windows ShellExecute or Explorer `/select`; runs in the user session. |
| Current-folder search, recursive search, content filters | Limited | Windows Search OLE DB is available on this PC. The current media folder is not indexed; the HTTPS search endpoint returned the matching file hit live there via the cancellable filesystem fallback. If the provider is missing or there is no index hit, the same fallback applies. Content search uses FREETEXT; the fallback searches known text formats up to 4 MB. If `es.exe` from voidtools is present next to the host or in the usual Everything installation folders, it is used for filename search with cancellation, paging, and server-side share/filter checks. The Everything CLI `es.exe` was not found in the detected installation locations including the host; its real CLI output has not been checked live here. Type, extension, size, and date filters apply recursively. |
| Properties, attributes, hash, version, ACL owner, OneDrive | Limited | Basic values, SHA-256/MD5, attributes, ACL/owner, EXE/DLL version, and OneDrive availability as far as Windows provides them. Folder sizes run in a separate worker that waits at most 20 seconds and allows only one blocked query per drive; an integration test simulates a hanging drive. The Windows shell property store adds capture date, image dimensions, camera make/model, and media length when a matching Windows handler is installed; media length was checked live with an MP3. The six Windows Known Folder entries are available here; the OneDrive environment root exists but does not redirect any of these folders. OneDrive placeholders and camera/EXIF metadata remain untested, and handlers do not provide values for every codec. |
| VoiceOver, Dynamic Type, rotation, large touch targets, dark mode | Limited | All dialogs are semantically marked up; focus is moved into them and trapped, Escape closes the top dialog, and focus returns to the trigger. Nested properties and preview dialogs plus file-name entry and an unsaved editor are checked in WebKit. On supported iOS WebKit, `-apple-system-body` reads the system text size; **Settings → Text size** additionally multiplies the base by 100 to 200 percent. The size is re-measured when reopening, rotating, and changing the viewport. The iPhone WebKit E2E test simulates system bases of 20 and 24 px and checks 200% scaling plus re-measurement when returning to the page; it also checks 320 px width, accessible names, breadcrumb labels, and at least 44×44 px for visible buttons and selection fields. Labels have at least 12 px at default size; the 320 px test checks that. Manual Dynamic Type and VoiceOver testing on a real iPhone is missing. |
| German PWA UI and later translatability | Done | Visible PWA texts including dynamic actions, feedback, counters, and date/number/size formatting are centralized in `src/Explorer.Web/src/locales/de.ts`; the WebKit E2E check passes after this change. |
| Additional device protection | Done (optional) | Numeric PIN hashed with PBKDF2-SHA-256, HTTP-only session bound to the allowed Tailscale identity, server-side API lockout, five failed attempts with 15 minutes lockout, session expires after eight hours. PIN can be set, changed, locked immediately, or turned off in “More”. iOS Face ID/Passkey via WebAuthn is not implemented; the PIN fulfills the alternative PIN requirement. |
| Structured log rotation and write log | Done | JSONL with evaluable properties and rotation, 8 files of up to 10 MB each. Successful file jobs, uploads, text saves, attribute and recycle-bin changes, and PIN security actions are logged; pure reads are excluded. |

## Measurements still open

- Install the PWA via the configured MagicDNS name on the iPhone and test cellular/Wi-Fi switching. The iOS peer currently responds to Tailscale ping over DERP; app installation and Safari access on the device are still not directly tested.
- Measure Safari scrubbing over Tailscale and a 2 GB upload after interruption on a real iPhone; repeat the 50,000-entry test on slow or remote drives.
- Test photo/video metadata and OneDrive placeholders on suitable real files, plus recycle-bin behavior on USB/network drives. HEIC, MP4, and PDF thumbnails have been tested with test files via the Windows shell; real camera/EXIF data remains format- and handler-dependent. The PC currently has no removable or network drives mounted; restore and owner display were tested live on NTFS on the target PC.
- The default action “Move to recycle bin” is refused on UNC network paths and Windows drive types `Network` and `Removable` before the shell operation. Unit tests cover UNC/UNC long paths and unsupported drive types; this preserves the file. Permanent deletion remains separate and requires confirmation in the iPhone menu.
